# Requirements traceability

Tests reside in `src/test/java/com/example/hms/careflow`. `WorkflowIntegrationContract` runs through both `WorkflowIntegrationTest` (H2) and `WorkflowPostgresIT` (PostgreSQL). PostgreSQL behavior is the acceptance evidence for transaction/concurrency guarantees; H2 provides faster feedback.

| Requirement | Implementation | Verification |
| --- | --- | --- |
| CF-01: Never oversell | Inventory row write lock; stock invariant checks; SQL CHECK constraints | `InventoryItemTest.oversellLeavesStockUnchanged`, `secondReservationCannotTakeLastUnit`, `WorkflowIntegrationContract.CF01_atomicReservationPreservesTotalStock`, `CF01_insufficientStockRollsBackStateAndAudit`, `databaseConstraintRejectsNegativeStock`, PostgreSQL stress below |
| CF-02: One fulfillment | Request row lock; global unique key; unique receipt/request; immutable receipt fields | `CF02_sameKeyReturnsExactlyTheOriginalReceipt`, `CF02_differentKeyCannotFulfillSameRequestTwice`, `CF02_keyCannotBeReusedAcrossRequests`, `WorkflowPostgresIT.CF02_oneThousandConcurrentRetriesCreateOneFulfillment` |
| CF-03: Authorization | Actor role checks, ownership checks, independent reviewer | `WorkflowPolicyTest` role/ownership cases, `CF03_selfApprovalIsForbiddenEvenForAdmin`, `CF03_requesterCannotApprove`, `CF03_requesterCannotReadAnotherOwnersRequest`, `apiRejectsUnauthenticatedRequests`, `apiRejectsUnauthorizedInventoryWrite`, `apiRestrictsGlobalAuditToAdministrator`, `apiHidesOtherOwnersAuditHistory` |
| CF-04: Atomic rollback | One transaction for stock, state, audit, receipt, and inherited outbox | `CF01_insufficientStockRollsBackStateAndAudit`, `CF04_outboxFailureRollsBackStockStateAndAudit`, `databaseConstraintRejectsNegativeStock` |
| CF-05: Audit successful changes | Creation and every state transition inserts actor/resource/previous/new/time; inventory updates require reasons | `CF05_everyTransitionHasPersistentActorAndStates`, `CareFlowServiceTest.rejectionIsAudited`, `cancelReleasesExactlyOnce`, `expiryReleasesStockAndRecordsSystemActor`; browser request-history and administrator-ledger tests |
| CF-06: 1,000 competing operations | PostgreSQL locks serialize allocation; bounded 32-worker workload | `WorkflowPostgresIT.CF06_oneThousandCompetingRequestsCannotOversellLastUnit`: 1,000 approved requests, one unit, exactly one reservation, 999 conflicts, final available zero |
| Explicit lifecycle | Complete transition map; all terminal states reject further transitions | `WorkflowPolicyTest.allStatePairsHaveExplicitRules`: all 49 state pairs; `apiReturnsConflictForOutOfOrderTransition`, `CareFlowServiceTest.cannotReserveBeforeApproval`, `approvalDoesNotTouchInventory` |
| Expiring reservations | UTC deadline, scheduler and staff expiry both use locked service transaction | `expiryReleasesStockAndRecordsSystemActor`, `expiredReservationCannotBeFulfilled`, `CareFlowServiceTest.earlyExpiryDoesNotReleaseStock` |
| Device traceability/holds | Synthetic UDI + lot uniqueness, expiry date, quality hold, source lot retained by request | Inventory unit tests for expiry/quarantine; `qualityHoldAfterReservationBlocksFulfillmentButAllowsRelease`; browser inventory search/hold test |
| Notifications | Reused transactional outbox with LOW_STOCK/SUPPLY_FULFILLED events | `lowStockAndFulfillmentUseFoundationOutbox`, rollback failure test, inherited channel tests |
| Upgrade existing hospital database | Flyway V2 widens the original role CHECK constraint while preserving users | `WorkflowPostgresIT.upstreamRoleConstraintIsMigratedWithoutLosingExistingUsers` |
| Input validation | Bean Validation, bounded list pages, positive quantities, required reasons/header | `apiRejectsInvalidQuantity`, `apiRequiresIdempotencyHeader`, `apiBoundsPagination`, unit invalid-quantity and overflow cases |
| Processing-time target | Repeatable HTTP workflow versus explicitly modeled manual handling overhead | `scripts/processing-benchmark.mjs`; `target/benchmarks/processing.json`; not a real-world time study |

Local verification includes 90 added unit executions (22 inventory, 61 policy, 7 Mockito service), 24 added integration scenarios, two PostgreSQL stress tests, and one legacy-schema upgrade test. The 61 policy executions include 49 parameterized state pairs; this is not 61 separate test methods. Four upstream authentication and two upstream notification tests are preserved. Browser coverage adds six end-to-end scenarios, including a cross-role workflow and mobile overflow check.
